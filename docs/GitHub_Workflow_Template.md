# 📋 قالب سير العمل على GitHub — للمشاريع القادمة

> **طريقة الاستعمال**: انسخ القالب من القسم التالي والصقه في **أول رسالة** عند بدء أي مشروع جديد، واملأ الفراغات بين `< >` قبل الإرسال.

---

## القالب الجاهز للنسخ

```text
استعمل GitHub بنفس منهجية مشاريعي السابقة:

1) المستودع: ارفع المشروع إلى github.com/saidjte/<اسم-المشروع> على فرع main
   باستعمال التوكن. التزم برسائل commit واضحة لكل تعديل.

2) البناء: أضف سير عمل GitHub Actions يبني APK للأندرويد
   (arm64-v8a + armeabi-v7a) عند كل push إلى main.

3) عند كل إصدار جديد:
   - زد versionCode بمقدار 1 وحدّث versionName (v0.X.0).
   - وقّع APK بنفس المفتاح وبنفس بصمة التوقيع الثابتة حتى يتمكن
     المستخدمون من التحديث فوق النسخة القديمة مباشرة دون حذفها.
   - شغّل سكربت تحقق (versionCode / المعماريات / بصمة التوقيع) قبل الرفع.
   - أنشئ Release يدوياً عبر REST API — لا تعتمد على CI لأنه
     لا ينشئ Release، بل يرفع Artifacts فقط.
   - ارفع إلى الـ Release: ملف APK باسم موحّد
     (<اسم-المشروع>_vX.Y.Z.apk) + حزمة مصدرية عبر
     git archive --format=zip --prefix=<اسم-المشروع>/.
   - تحقق أن رابط التحميل المباشر يعمل (HTTP 200 أو 206) قبل إعطائه لي.
   - أعطني دائماً: رابط صفحة Release + الرابط المباشر للملف.

4) وثّق كل خطوة وكل درس متعلق بالنشر في worklog.md
   (مثل: "CI لا ينشئ Release — الإنشاء اليدوي إجباري").

5) حدّث صفحة المعاينة (Preview) بروابط التحميل الجديدة بعد كل إصدار.

بيانات المشروع:
- التوكن: <ضع التوكن هنا، أو استخرجه من remote إن كان المستودع مستنسخاً محلياً>
- بصمة التوقيع الثابتة: <SHA-256 fingerprint الخاص بمشروعك>
- ترقيم الإصدارات: يبدأ من v0.1.0 مع versionCode = 1
```

## ملاحظات مهمة

### 1. التوكن
كل جلسة جديدة لا تتذكر ما سبقها، لذلك:
- احتفظ بالتوكن عندك وأعطه في أول رسالة من كل جلسة، **أو**
- إن كان المستودع مستنسخاً محلياً ضمن مسار المشروع، يمكن استخراجه تلقائياً:

```bash
git remote get-url origin | sed -E 's|https://x-access-[^:]*:([^@]+)@github.com.*|\1|'
```

### 2. بصمة التوقيع الثابتة
هذه أهم نقطة للحفاظ على **التحديث المباشر** (تثبيت النسخة الجديدة فوق القديمة دون حذف بيانات المستخدم):
- احتفظ بملف `keystore` وكلمة المرور خارج الجلسات.
- أعطني مسار الملف وكلمة المرور في بداية كل مشروع، ثم لا تغيّر المفتاح أبداً طوال عمر المشروع.
- مثال من مشروع Atlas Drift: `0A:06:7C:71:36:1C:21:9E:4C:61:3B:3B:A5:13:05:07:1F:DA:E2:CF:28:11:1E:72:A6:27:E1:35:2A:0E:29:71`

### 3. الدرس الأهم (لا تنسه)
CI على GitHub Actions يبني **Artifact فقط ولا ينشئ Release** —
إنشاء الـ Release يجب أن يكون **يدوياً عبر REST API** في كل إصدار.

### 4. للمشاريع غير الأندرويد
نفس القالب يعمل، فقط استبدل "APK" بنوع المخرجات المطلوب:
- لعبة Godot لسطح المكتب → Windows/Linux builds
- لعبة ويب → Web export (HTML5)
- تطبيق ويب → لا حاجة لبناء، الرفع مباشر
